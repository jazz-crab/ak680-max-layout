## Мышь ZELOTES C-18 (соседняя периферия)

Мышь `12c9:2003` («SOAI USB Gaming Mouse»), в OpenRGB **не поддержана**. Протокол
полностью раскодирован: https://github.com/PadreAdamo/c18_reverseengineer
(`PROTOCOL.md`: режимы off/static/breathing/neon/wave/flowing, транзакции
begin→payload→commit, checksum `0xFF − sum(байты 0..6)`). Рабочий CLI на libusb — `c18ctl`.

      курсор замрёт до переподключения USB (подробности — README.md).

## OpenRGB — решение (форк НЕ делаем)

- [x] **Не форкать OpenRGB ни для AK680, ни для C-18** (зафиксировано 2026-09-13).
      Причины: (1) ни одно устройство в OpenRGB не поддержано; (2) контроллеры
      компилируются в ядро (плагинов нет) → форк = два своих драйвера + поддержка
      сборки большого C++/Qt проекта; (3) узкое место — сток-прошивка RY5088:
      per-LED стриминга в ней нет (`0xE8` — только после MONSMOD-патча), т.е. даже
      OpenRGB дал бы тот же путь «запись UserPic/режима», что уже есть в `iot_driver`.
      Пути остаются: AK680 → `iot_driver` (+ маленький демон для реактива), C-18 → libratbag.
      Задел на будущее (если когда-нибудь понадобится драйвер в OpenRGB): прецедент
      per-LED для RY5088-семейства — контроллер Skyloong GK68HE Pro (`3151:5029`)
      через запись UserPic; детектор для AK680 — по `3151:502D` + dev_id 2255
      (USB PID переиспользуется между моделями, dev_id — надёжный дискриминатор).
