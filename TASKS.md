## Раскладка

- [x] **` на углу, Esc на Caps** (2026-10-25/26): `1` (физический Esc) → grave (в EN
      это `` ` ``/`~`, в RU — ё), `3` (CapsLock) → Esc. CapsLock убран. Раскладка
      английская, поэтому на картинке и в README клавиша называется `` ` ``.
- [x] **Ё без Fn (Mod-Tap)** — рецепт в `README.md` → «Ё: удержание „е“ (Mod-Tap)».
      **Отвергнут при реальном наборе**: при пороге 200 мс клавиша «е» печатается с задержкой
      (при быстром наборе следующий символ успевает раньше «е»). Сейчас на клавише обычный
      режим (Normal), ё = угол (бывший Esc), запасной способ — `Fn+«е»`.
      Двойной тап через `set-key-trigger --mode toggle-dots` тоже **не подошёл**: прошивка RY5088
      в этом режиме включает автоповтор выхода (буква печатается до повторного тапа), т.е.
      это переключатель-залипание, а не «двойной тап → второй символ». DKS (`dks`) — это
      триггер по глубине нажатия, а не по двойному тапу, для «е/ё» не подошёл бы (набор до дна).

## Мышь ZELOTES C-18 (соседняя периферия)

Мышь `12c9:2003` («SOAI USB Gaming Mouse»), в OpenRGB **не поддержана**. Протокол
полностью раскодирован: https://github.com/PadreAdamo/c18_reverseengineer
(`PROTOCOL.md`: режимы off/static/breathing/neon/wave/flowing, транзакции
begin→payload→commit, checksum `0xFF − sum(байты 0..6)`). Рабочий CLI на libusb — `c18ctl`.

- [x] **Подсветка C-18 готова** (2026-09-13): статичный цвет управляется
      `bin/mouse-color.sh` через `c18_usb_seq3` (только интерфейс 2, vendor).
      **ВАЖНО**: не detach интерфейсы 0/1 (ввод мыши) — usbhid не вернётся,
      курсор замрёт до переподключения USB (подробности — README.md).
      Дальнейшее: DPI/кнопки — через **libratbag** (см. ниже).
- [ ] Оставшийся путь — **libratbag**: чистый и mergeable PR #1877 «Add: SOAI C18
      gaming mouse driver» (ветка `soai-c18-driver` в форке PadreAdamo/libratbag,
      1287 строк; LED/DPI/кнопки проверены через `ratbagd`/`ratbagctl`).
      Варианты: дождаться мержа в апстрим / применить PR в локалке / пользоваться
      `c18ctl` уже сейчас.

## OpenRGB — решение (форк НЕ делаем)

- [x] **Не форкать OpenRGB ни для AK680, ни для C-18** (зафиксировано 2026-09-13).
      Причины: (1) ни одно устройство в OpenRGB не поддержано; (2) контроллеры
      компилируются в ядро (плагинов нет) → форк = два своих драйвера + поддержка
      сборки большого C++/Qt проекта; (3) узкое место — сток-прошивка RY5088:
      per-LED стриминга в ней нет (`0xE8` — только после MONSMOD-патча), т.е. даже
      OpenRGB дал бы тот же путь «запись UserPic/режима», что уже есть в `iot_driver`.
      Пути остаются: AK680 → `iot_driver` (+ маленький демон для реактива), C-18 → libratbag.
      Задел на будущее (если когда-нибудь понадобится драйвер в OpenRGB): прецедент
      per-LED для RY5088-семейства — контроллер Skyloong GK68HE Pro (`3151:5029`)
      через запись UserPic; детектор для AK680 — по `3151:502D` + dev_id 2255
      (USB PID переиспользуется между моделями, dev_id — надёжный дискриминатор).
